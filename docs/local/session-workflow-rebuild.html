Correction (2026-08-27): the cache figure was measured with the same prompt twice. Production never does that — every drive job carries a different --append-system-prompt, which breaks the prefix. Re-measured with differing prompts, ~19k of ~45k tokens hit cache and 25,700 are recreated per job; the payload reports ephemeral_1h_input_tokens, a 1-hour TTL against a 67-minute p50 job. "The session is already warm" is false. The startup ratio above still holds — it is scale-invariant — but it was never the load-bearing argument.

Withdrawn: one session per issue, held across the park. Three findings kill it independently — the answer has nowhere to go (a running job makes answer-resume a swallowed no-op via jobs_active_unique), the 25 s synthetic heartbeat would make a park report progress forever (principle №10), and a held job takes both the project and runner slot, where forge-dev already has 7 parks against a cap of 3.

It was also priced wrong: the 758 h belongs to on_hold — core's cancel-park, no question pending, no session to hold. The population it would serve is 3 issues, and drive jobs do not take the --resume path it was built around (resume-policy.ts:145; resume_failed fired 0 times in 90 days).

Do instead: needs_info is absent from NOTIFY_ON_STATUS while waiting — the park nothing wakes — is present. All 17 parked issues have zero human replies. The question is asked on a surface no human reads; fix that first, then alarm an aged park, then thicken forge_phase resume_point.

What this does not solve

  • A held session still burns a runner slot for the whole park. Today's dead process does not — so this trades 758 hours of lost context for capacity held open, and the cap needs a policy for how long a session may wait before the runner gives the slot back.
  • A runner restart kills every held session. The --resume path does not go away; it stops being the normal path and becomes the recovery one.
  • The three non-resuming parks are untouched. waiting and on_hold are stopped by a person and no answer restarts them — that is S2, and it is the rule the new checker holds the skills to.
