Duplex agent session — architecture

A running agent gets an inbox. One session per job; resident while working, durable while waiting. Nothing pooled. This is RFC 0003 drawn: the components, the state machine, the queueing rule, and the one flow that is subtle.

Build order

#LandsUseful on its own because
1DuplexClaudeRunner behind sessionMode: 'duplex', work onlyone message, one turn, one result — effectively print mode, so it proves the plumbing writes a line and reads a reply. It does not prove a session survives a turn: claude_code.rs:651-666 tears the child down RESULT_EXIT_GRACE = 5 s after the first result line, and result_seen / num_turns / succeeded are all derived per-job from that same marker. Inverting that terminal model is the real work and it lands here, not in phase 2
2TurnEnded + core classification + runtimeStateturn-end classification replaces inference-from-silence for the anomaly case — a turn that ended with the work unfinished becomes a reported fact instead of a 60-minute timeout. At residency 0, awaiting_input exists for milliseconds and nothing observes it, so the working-vs-awaiting-input dashboard needs phase 3, not this row
3answer + ack-is-commit + the residency timerthe park fast path; safe at every residency value including 0
4inject, checkpoint, cancel replacing signal-killsteering a live agent, and a teardown that writes down what it knew

Chat goes first. daemon/chat.rs is a conversation that has been running one-shot the whole time and needs no residency window at all — so it exercises send end to end before any pipeline job depends on it.

Lockstep, and what this does not do

  • forge-drive/SKILL.md — "then end your session" becomes "then finish your turn". Ships with phase 3, never earlier: under sessionMode: 'print' waiting really is a lie.
  • jobs/loop-monitor.ts — the quiet computation reads runtimeState. Phase 2.
  • docs/architecture/runner-daemon.md — the spawn description. Phase 1.
  • Not addressed: nothing here changes how often a job fails or who gets told that a question is waiting. This is a capability, not a remedy for either.
