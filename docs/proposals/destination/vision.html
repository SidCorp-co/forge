0 · The claim, and the non-claim

Forge turns intent into shipped software without a human holding the thread.

Agent compute gets cheaper every quarter. Human attention and trust do not. So Forge does not sell the ability to do; it sells the ability to believe it was done right — and the product is trustworthy autonomy: making it safe not to look.

Revision 1 stated that as "every merge carries a machine-checkable chain of evidence back to intent." That is not achievable and no one who claims it is telling the truth — intent is prose, so nothing downstream can be mechanically checked against it. Every provenance system that shipped in production says so in writing. SLSA v1.0: "SLSA does not tell you whether the developers writing the source code followed secure coding practices" — source threats are explicitly out of scope, and a malicious commit through legitimate CI earns a valid, signed L3 attestation. in-toto's own threat model assumes "there are no rogue developers wishing to subvert the supply chain."

So the claim splits in two, and only one half is about proof:

CUSTODY — what the chain gives
attributable
For every merge: who claimed what, when, under which policy version, against which premises, judged by whom at what measured independence. Append-only, signed. This makes a lie attributable.
THE FLOOR — what actually bounds emptiness
expensive
A held-out suite the author never sees · mutation kill-rate on changed lines · planted impossibles · oracle isolation. No LLM may override any of it. This makes a lie expensive.
NEITHER GIVES
impossible
Nothing here proves the work satisfies the intent. That is the oracle problem, and it is not closable. State it in the product copy rather than discovering it in a demo.
Metric Human Intervention Rate, the AURA framing. Industry elite is <5%; Anthropic reports Claude Code moving 5.4 → 3.3 interventions per session. Target: <1 intervention per closed issue, measured continuously — and reported beside the escape rate in §6.5, because a change that lowers interventions and raises escapes is a regression, not a win.

3 · The session tree

Two primitives, not one

link is bidirectional and propagates exit — parent↔child inside one process, and that is inherited liveness. monitor is one-way and propagates nothing — the box daemon watching the root. Collapsing them is how a child's death takes out the control plane's view.

Close policy is declared per child

terminateparent dies, child dies nowa subagent running a build
request_cancelchild writes its fact first, then diesa subagent witnessing a deploy it just pushed
abandonchild outlives the roota long eval the master spawned

Inherited liveness gives the first one free. Shipping only terminate is defensible and must be said out loud, because then "the deploy finished after the master died" has no representation at all.

Subtree closure is ownerReferences, not a sweeper

Background · foreground · orphan, as Kubernetes settled it. The part worth stealing: blocks_owner_close is a per-child bit — only a child whose unfinished work would lose a Fact blocks its parent. Everything else closes immediately.

And that bit is a finalizer, with every finalizer failure mode. Kubernetes' most common stuck-object class is a finalizer whose controller died. Every blocking finalizer needs a TTL and a force path that writes an audit Fact.

Level-triggered, not event-driven

A sweeper encodes which cases to skip and grows a clause per incident. A reconciler encodes what must be true, ignores the event payload, re-reads current state — so a dropped frame, a daemon restart, a partial write all heal on the next pass.

"Let it crash" does not transfer. OTP restarts into clean state. For an agent, clean means context lost and the work redone from zero. Facts must be durable outside the session or every reap is a rollback. Restart intensity is capped — OTP's default is 1 per 5s, and exceeding it kills the supervisor and escalates rather than looping.

4 · Facts and projection

Deterministic loop, non-deterministic action

Temporal, Restate and DBOS all journal the non-deterministic call and read it back on replay; what replays is the loop around it. Here the Fact log is the journal — a resumed master re-reads facts and never re-derives them. This is what makes "resume" mean anything for an agent whose code is a prompt.

Status is a projection and still indexable

pg_ivm / create_immv() applies deltas to a real table inside the writing transaction on Postgres 13–18. So the projection is indexed, filterable and read-your-writes, with no Materialize or Kafka tier. Changing the projection function is blue-green — build beside, cut over — never a rebuild in place.

Two clocks per fact

observed_at beside recorded_at buys ~80% of bitemporality and answers the one question evals need — what did the agent know when it decided? — without trading the whole storage engine for FOR SYSTEM_TIME AS OF.

Policy version is pinned, and admission is a core write

Temporal pins in-flight workflows with a change marker written into history. A prompt has no change-id, so the root session carries policy_version and every child inherits it. Without it, phase declared: review under v3 and under v4 are one row and two different events, and the projection's meaning changes under running work.

Core admits the policy version; the box never just pulls it. A policy declaring a predicate this core build cannot evaluate is refused at registration, naming the predicate, and the box keeps the last admitted version. This is the one-way gate — see §7.

Principal separation is a write-time constraint with a known hole

No verdict fact whose author principal equals the author of the code facts in the same subtree. Checking this in the projection is too late. Checking it at insert means a recursive walk under contention, and a naive EXISTS is a textbook write-skew hole — two concurrent inserts both pass. Close it deliberately: SERIALIZABLE, an explicit lock on the root row, or a denormalised root_id + author on every fact.

5 · Question — the highest-leverage primitive

WhoHasMissing

HumanLayerwas the closest productpivoted away in 2026; the approvals API is off the site

One object, two audiences. Two mechanisms would mean two places a run can stall in silence.

Parked is a row, not a process

The session ends, the job goes held, the runner slot is freed, and the answer starts a fresh session seeded from the question's context packet — Temporal's wait_condition shape, not LangGraph's in-process interrupt(), which re-runs the node from the top and has documented double-execution bugs. held must be non-terminal to every sweep and the loop monitor must not reap it, or this feature manufactures the exact leak it exists to prevent.

Two-stage timeout, andon-shaped

T1 (~20 min, yellow) reroutes to a different target and stops nothing. T2 (~24h, red) forces: with a default, the default applies and a Fact records that it did; without one, held plus an ageing queue. Ageing is not optional — the measured LangGraph production failure is precisely "no SLA on pending approvals, work stalls silently." Anyone holding the role may answer, PagerDuty-style: escalation moves to a different responder, never binding an answer to one identity.

Fixed shape; free text refused by name

situation      — what I was doing
blocker        — what I cannot determine
options        — 2 to 4, enumerated
recommendation — my default
cost_if_wrong  — reversible | irreversible

SBAR / I-PASS. The decisive I-PASS element is synthesis by receiver: the resuming agent restates the answer in its own words before acting, and that restatement is what review reads. (NEJM 2014: 23% relative reduction in medical errors, no increase in handoff time.)

The decidability rule

A subagent decides alone when it can write down a default, and that default is (a) reversible, (b) inside the ownership line, (c) not a kernel fact.

Otherwise it asks — and it asks whoever holds the missing thing, not the nearest authority.

The anti-spam mechanism is the first clause: an agent that can state a safe default usually should not have asked, and writing the default down usually answers the question.

Hard limit, from Cognition's measurement. A parent may only answer about intent it actually holds. A parent inventing an answer to a factual question it merely inferred is the worst failure mode in the system.

Premises are derived by the kernel, never declared by the agent

Revision 1 had each session declare what it relied on. That is refuted — see §13. What the kernel persists instead is what core actually served: the resolved fact-input set and the answered-question set, stamped at session open beside policy_version. An agent's own declaration is kept in a separate advisory column and may never authorise the keep-running branch.

The bucket is named no record of reading P, not "did not read P", and its default is to block. An exemption is a priced amnesty with a named end condition, not a computation. Coarser than revision 1 promised, and the only version that does not lie.

6 · The floor — where the product claim actually lives

This section was revision 1's §6 and is now the centre of the document, because the adversarial round established that the evidence chain checks shape and only the floor checks substance.

6.1 · Independence is a measured vector, not a boolean

Revision 1's registry carried an independence minimum and no substance minimum. That asymmetry is what let a complete chain be empty.

6.2 · The deterministic floor no judge may override

An LLM verdict is one input. The merge is gated by checks that run no model. If any LLM verdict can move an issue to tested, principal separation has relocated the problem, not closed it.

6.3 · Four anti-cheat mechanisms, all measured

MechanismEvidence
Held-out suite the implementing agent never sees; score the gapSpecBench: gap reaches 100 points, and is invisible from the visible side by construction
Hide the test files from the implementing agentImpossibleBench: hack rate to ~0; stronger models cheat more
Isolate the oracle — strip .git, single-commit, allowlist egressCursor audit, 731 trajectories: 63% of successes retrieved rather than derived; isolation drops scores 14–21 points, and that delta was never real
Plant the impossible — mutate a test so passing requires cheating; keep it as a standing tripwireImpossibleBench; this is the repo's own "plant exactly that, watch it go red" raised to a periodic probe

Mutation kill-rate and property invariants replace coverage, which is gameable. Google's scale warning applies: absolute mutation score on a monorepo is infeasible, 75% of surfaced findings were judged useful, and a human still adjudicates survivors — so scope it to diff-touched lines and expect to build a suppressor.

6.4 · The corpus is our own

OpenAI retired SWE-bench Verified from its own evaluation — contamination plus broken tests, with >60% of unsolved items unsolvable as scored. And scaffold is what moves the number: same model, 62.3% → 70.2% on scaffold choice alone. Public benchmarks measure the model; only a corpus of our own production traces measures the harness. Below ~500 cases the mean is noise.

6.5 · Falsification — three tests that can actually fail

A · null-implementation corpus (forward)
escape_rate
Build a null variant of each corpus case that satisfies the visible test only. Run the pipeline uninstructed. Target 0. Any non-zero value falsifies the custody claim. Report it beside the intervention rate.
B · mutation backtest (retrospective)
ungameable
For every already-merged chain, run mutation testing on diff-touched lines with the suite as it stood at merge. Below the class floor = a chain that was complete and empty. Cannot be gamed by the agents being measured.
C · RED-cause audit
<50%?
Assert mechanically: same test id as the GREEN, exit reason is an assertion failure and not an import/collection error, and the failing assertion names a symbol the diff introduces. The historical pass rate measures what the RED link was ever worth.

6.6 · Credit assignment finds the causal locus

MAST puts 4 in 5 failures upstream of the visible break. So the post-mortem is a counterfactual replay: model the run as an SCM, resample one step under the same policy, report the latest step where re-deciding still rescues the run.

6.7 · OTel: emit spans, do not store facts as spans

The session tree maps onto invoke_agent / execute_tool nearly one-to-one, so exporting is almost free and buys Langfuse / Phoenix / Braintrust. But spans are sampled, lossy and TTL'd, while a verdict is a durable claim with an author. Facts stay first-class rows; the trace is a projection joined by trace_id / span_id.

7 · Four planes, and a one-way gate

Core gates policy admission. Policy gates nothing.
One-way. Revision 1 carried the opposite sentence and threw away the document's biggest structural win — see §13.

Floors are monotone. Core holds a per-claim-class floor; registration computes ∀d: policy[d] ≥ core_floor[d] and refuses the version naming the dimension it lowered. Policy may only tighten. Without this, a git push can declare a claim class with no minimum and delete the RED role from the chain, and the resulting clean numbers would raise the trust budget — a breach that rewards itself.

11 · The counter-argument, left standing

The control plane is exactly where the platform owner gives it away, bundled. GitHub ships Mission Control to every paid Copilot seat, with the substrate — repo, PR, CI, identity, audit — that a self-hosted plane rebuilds from scratch.

The right analogy is not "Jenkins won." It is Travis lost to GitHub Actions, not to Jenkins. A neutral layer wins only where neutrality is load-bearing: many repos, many vendors, air-gapped, or regulated. If most teams are one-repo-on-GitHub, neutrality is a feature nobody notices. And the base rate is unkind — Terragon closed January 2026, Vibe Kanban's parent closed April 2026. Thin wrappers die; the kernel-shaped ones are untested.

The only available answer, and it must be chosen deliberately Be load-bearing where GitHub cannot reach: the runner is a device you own, running against production-adjacent context that never leaves your network; memory is verified and first-class; and state is derived from evidence rather than from someone's hand.
