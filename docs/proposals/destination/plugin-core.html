Plugin, Core, Runner

The driver skill lives in a second repository. This is the surface it reaches core through, what versions that surface today, and where the version is dropped.

1 · Three transports, one database

Measured on main, 2026-09-20. The invariant that keeps MCP off the database holds by fact and by nothing else: .arch.json declares eight contracts and none of them mentions core-mcp. An unguarded invariant is one careless import from being untrue, and nothing will say so.

One of five carries a version, and §3 is where that one is dropped.

3 · The pin, and the case that removes it

A conflict is a question for a human — which SHA does this box run? Answering it by removing the constraint turns a stated disagreement into an unstated one, and the box then runs a driver nobody chose against a core that declares five statuses and three endpoints with no handshake.

5 · What this page replaced

docs/proposals/cli-data-surface.html made the same argument and was deleted rather than carried. It was written in Vietnamese in a tracked file, and every number in it had drifted: 45 MCP tool modules against today's 37, 107 route mounts against 130, and four named REST gaps (forge_divergence_charters, forge_ux_improver, forge_ops_health, forge_version) that no longer exist as tools at all. It also credited the MCP-off-the-database invariant to a test file, no-transport-db.test.ts, which is not in the tree. Its one surviving idea — REST as the single plane, MCP as a thin adapter — is row 4 above.
