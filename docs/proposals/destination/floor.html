The Floor

The chain makes a lie attributable. The floor makes it expensive. This page is the second half, and it is where the product claim actually lives.

1 · Why a complete chain can be empty

2 · Four mechanisms, four owners

Four different owners is the point. A mechanism whose owner is the agent being measured is not a mechanism.

3 · RED-cause — the cheapest link, and the most decorative

4 · Both minimums, declared per claim class

Floors are monotone: policy may only tighten them.
Core holds a floor per claim class; a policy version that lowers any dimension is refused at admission, naming the dimension. Otherwise a push can declare a class with no minimum, and the clean numbers that follow would read as improvement.

6 · Falsification — three tests that can come back wrong

TestHow it fails, and why it cannot be gamed
Aescape rate — build a null variant of every corpus case that satisfies the visible test only, run the pipeline uninstructedTarget 0. Any non-zero value falsifies the claim directly. Report it beside the intervention rate — a change that lowers interventions and raises escapes is a regression, and without both numbers it looks like a win
Bmutation backtest — for every already-merged chain, run mutation on the diff lines with the suite as it stood at mergeRuns against the past, so the agents being measured cannot influence it. Every result below the floor is a chain that was complete and empty
CRED-cause audit — assert the three conditions retrospectivelyMeasures what the RED link was ever worth. Prediction: below 50%. If so, drop the link rather than enforce it
The stated test in revision 1 was too weak. "Inject a lying state and the kernel refuses" only probes the cases the kernel already models. None of these three do — they probe work that is structurally complete and semantically empty, which is the failure that actually happens.
