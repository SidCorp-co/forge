issue-work-module-diagram-generation — how a module taxonomy becomes four diagrams, and every hop that refuses

ISS-950, Tier 3c of ISS-587. issue-work-module-knowledge-refresh owns how a node stops being stale; web-v2-module-taxonomy owns the slug and the 1:1 node binding. This file owns what happens when somebody asks for a diagram: which rows are read, which of the four kinds reads which of them, and where a request is refused by name rather than answered with a picture that looks complete. Owners: packages/core/src/labels/module-diagram-routes.ts, packages/core/src/labels/module-diagram-source.ts, packages/core/src/labels/module-diagrams.ts.

When it goes wrong

What failsWhat the caller seesWhy not the other thing
The project has no kind='module' label409 NO_MODULES.Not a 200 with an empty mindmap: an empty frame and a project nobody has classified render identically, and only one of them is a diagram.
No module's node stores a Mermaid flow409 NO_MODULE_FLOWS — on user-flow and swimlane only.mindmap and context never read a flow, so the same project answers them normally. A refusal that applied to all four would report the absence of one input as the absence of the taxonomy.
A stored flow uses Mermaid the reader does not understandThe whole request is 409 UNPARSABLE_MODULE_FLOW, naming the module's slug.Not "the modules it could read". A diagram missing one module's steps is indistinguishable from that module having none, and the reader has no way to find out which.
A module has no knowledge nodeNothing. It is drawn — its name, its place in the hierarchy, and no count.An unbound module is a legal state (labels_knowledge_entry_chk), not an error and not a row to skip silently. The absent count is the honest rendering of "nothing was counted".
A declared edge names something that is not a moduleThe edge is absent from the context diagram.Both ends must resolve or the arrow would point at a node that is not on the diagram. A triple resolving one end only is not an edge between modules.
A declared edge was retractedThe edge is absent.valid_until in the past is the only way a triple is ever withdrawn; a reader ignoring it draws a coupling somebody has already said is gone.
There is no cache, and that absence IS the regeneration rule. ISS-950 requires that a diagram cannot be quietly older than the node it claims to render. Nothing schedules a redraw and nothing stores one: the Mermaid is computed inside the request from the rows as they are, so there is nothing between the taxonomy and the response that could go stale. The client hook holds no staleTime for the same reason — a remembered diagram would put the staleness back.
Knowledge nodes are the source; issue_labels is read for exactly one thing. Every attribute of a module comes from labels, and every fact about a module comes from the node bound through labels.knowledge_entry_id. The one exception the epic admits is the context diagram's edge weights, which are how many issues a pair of modules shares and can come from nowhere else. A generator reading tags for anything more is the wrong shape.
docs/flows/ is not a target of this generator, and must not become one. The four kinds are a product surface, per project, rendered from live rows in the browser. This directory is this repository's own hand-drawn mechanism diagrams, backfilled by the work; generating into it would put churn in git on every issue close and replace mechanism drawings with component maps. Both surfaces exist and they answer different questions for different audiences.
