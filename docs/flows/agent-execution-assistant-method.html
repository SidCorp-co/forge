One method, every door

An assistant answers people in more than one place — a team chat channel, the Forge web app, and a streaming surface with no client of its own. How it should work a request is the same everywhere. This is where that method lives, how it reaches a turn, and what each place is allowed to add. Owners: packages/core/src/guides/assistant-method-guide.ts (the method itself), packages/core/src/assistant/door-persona.ts (what every door opens with, and the Forge web app's own lines), packages/core/src/integrations/rocketchat/persona.ts (the chat channel's own lines), packages/core/src/assistant/tools/registry.ts (whether the method can be fetched at all).

The method is stored once and fetched, never copied into each channel's voice. Before this, it existed in the chat adapter and nowhere else: the web app got one sentence, and a correction to any rule had to be made in every copy or it was not made. It is now a guide with a name, and every door's opening tells the model to read that name before answering. A sentence the guide carries appears in exactly one place, which is what makes a correction a one-line change instead of a search.

From a message to a turn that knows the method

What stays with a channel, and why each is false elsewhere

StaysWhereWhy it cannot be shared
Its own name, and how it refers to itselfchat channel Nowhere else has a bot name; in the app the assistant has no handle to use.
Whose "I" is whosechat channel A room has many speakers and one message names one of them. A one-to-one conversation does not need telling.
Read the older discussion backchat channel It names a way of reading a room that only that channel has. Telling another door to use it points at something it was never given.
Your reply is the only message there will bechat channel The sharpest one. True in a room; false in the app, where a person can reply — so shared, it would forbid a clarifying question the app exists to allow.
Plain text, no headingschat channel A chat client renders none of it. The app does.
No checkout and no shell; where a real session startsweb app It answers a loss that belongs to that surface, and names a screen only it has.
Which language to answer inthe project's settings It is a fact about a customer, not about a channel. It used to be hard-coded in the chat adapter, so a project in any other language was answered in one it never chose.
A guide nobody can fetch is worse than the prose it replaced. The method only became a pointer once the fetch was proved to work from a running door — the bot would otherwise have lost the method and gained an instruction it could not follow. That ordering is not a nicety: the two halves shipped as separate releases, and the first one changed no persona at all.
The assistant may read guides and may not write them. The same mechanism that serves the method also serves each organisation's own documentation for the systems it connects, and those are editable. A chat session is allowed the two reading actions and refused the two writing ones before the request reaches the permission check inside — because the person typing in chat may well hold the permission, and "they were allowed to" is not the same question as "a chat window should be able to".

What a person sees when it goes wrong

SymptomWhat it meansWhat to do
The assistant answers thinly, or asks for something it could have looked up It did not fetch the method this turn. The method is a document — read it yourself at the public guides URL and say which rule it skipped. That is a report about one document, not about a channel.
The assistant says it cannot find a guide The pointer and the stored document disagree — a rename that reached one and not the other. This is a defect, not a configuration: the name is written down in one place precisely so the two cannot drift.
Replies come back in the wrong language The project's reply style is empty or says something else. Set it in the project's integration settings. It is a per-project setting now; it used to be fixed for everyone.
A room's reply promises to come back later The one-shot rule was not followed; there is no later turn in a room. Report the reply. The rule is in that channel's own lines, not in the shared method.

Where the rules are carried

Pointers, not the rules themselves. packages/core/src/guides/assistant-method-guide.ts holds the method and the one spelling of its name. packages/core/src/assistant/door-persona.ts composes what every door opens with and the web app's own lines; packages/core/src/integrations/rocketchat/persona.ts holds the chat channel's five. packages/core/src/assistant/tools/registry.ts decides whether the method can be fetched and which actions a chat window may use. packages/core/src/assistant/persona-accounting.test.ts is the ledger that keeps every sentence in exactly one of those places.
