agent-execution-blocked-branch — which of four branches a blocked run takes, chosen by who can resolve it

A run that cannot continue asks one question first: who can unblock this? The answer decides whether the process is kept or released, and every clock that then applies. Getting it wrong is not a slow run — it is an unbounded wait holding a box, or a park a reaper eats. Owner of the decision: packages/runner/crates/forge-runner-core/src/runner/blocked.rs.

The fork

  P1 --> P2["declare exited x blocked

  P2 --> P3["process released
worktree + branch + resume_id kept"]
The order inside the bounded arm is the whole of it. The question row lands first, then the FIFO is opened for reading, and only then is the run declared blocked. The declaration is what tells a ringer somebody is listening — so declaring first puts a ring into a gap nothing reads. a_door_that_cannot_open_leaves_the_run_runnable holds it.
nobody is a failure with a name, not a question. It is refused before begin_question runs, because a row nobody can answer is indistinguishable from a run that is merely slow.

Why the human branch is the only one that releases

The two arms refuse each other's blocker by name rather than coping: arm_bounded rejects human and points at park_for_human, and park_for_human rejects the other two and points back. There is exactly one owner of that rule, so a caller cannot take the wrong branch quietly.

A park is unwritable without core's permission

Core and the runner deploy separately, so a new runner can meet an old core. A park written against a core whose reapers do not know about parks is a park that gets eaten — so the box asks:

sequenceDiagram
  autonumber
  participant R as forge-runner
  participant C as core
  R->>C: GET /api/devices/me/protections
  C-->>R: { protections: [...] }
  Note over R: ParkPermit::from_advertisement
requires EVERY name it knows
  alt all present
    R->>R: park_for_human(&permit)
  else any missing, 404, or unreachable
    R--xR: refused by name — the run KEEPS its process
  end

A 404 is a legitimate answer meaning “no protections”, not a fault: an old core has no such route. park_for_human takes the &ParkPermit as a parameter, so an unprotected park is not something a caller can write — it is not a boolean anyone can pass wrongly. Two of the names are the runner's own sweeps and are asserted from this binary's source, since core cannot observe which runner is asking.

One clock per premise, and no state under none. Four of the five spare the park and the fifth bounds it. The predicate lives in exactly one place per side — parkedOnAHuman in core, Run::is_parked_on_human on the box — because a fourth copy is how one reader keeps eating what the others preserve.
