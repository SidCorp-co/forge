What an issue carries, and who may write each part

one door per kind of write — never one per caller

1Every write goes through one door, whatever it arrived on

flowchart TD
  W1["a person typing in the browser"] --> D
  W2["an automated worker"] --> D
  D["one place decides
whether the write is allowed
and what it will actually store"]
  D --> C{"is the text well formed?"}
  C -->|"no"| R1["refused, naming what was wrong
and what a valid one looks like"]
  C -->|"yes, but not what was sent"| S["stored in the cleaned-up form"]
  C -->|"yes"| S
  S --> L["the history records what was stored,
never what was typed"]

Both entrances share one decision point, and that is the rule rather than an accident: a check placed on one entrance is a check on neither, because the other one still lets the same write through. The history recording the stored version — not the submitted one — is what stops the audit trail showing a value the issue never held.

2When a rule applies to machines and not to people

flowchart TD
  A{"who is writing?"}
  A -->|"a person"| P["never refused. At any stage, for any rule
of this kind. A tracker that rejects a
sentence somebody typed is a tracker
the project switches off"]
  A -->|"an automated worker"| M{"does this stage demand
a structured answer?"}
  M -->|"no"| M1["write it as prose"]
  M -->|"yes"| M2["must fill in the structure the stage asks for,
or be refused and told which part is missing"]

The point of demanding structure is to make an automated writer leave a record that can be read back by something other than a human eye. Extending that demand to people would buy nothing and cost the thing everyone actually uses.

3Modules — one primary, many secondary, never added together

flowchart TD
  I["an issue"] --> PR["one primary module — where this work mainly lands"]
  I --> SE["any number of secondary modules — what it also touches"]
  PR --> CNT{"counting the backlog by module"}
  SE --> CNT
  CNT --> Q1["primary and secondary are counted apart.
Adding them together counts one issue twice"]
  CNT --> Q2["a parent module's count folds in its children,
counting each issue ONCE even when it is
attached to the parent and the child both"]

An issue carrying no module at all is a distinct answer from an issue attached to nothing countable — the two must not collapse into each other, or work with no owner disappears from the report that exists to find it.

The shipped markasserted by whoever landed the work

The shipped mark is the only part that is a claim about the outside world. Everything else describes the issue; that one describes the product.

Two writers, one field

When two workers change the same field at once, the second does not silently overwrite the first. A write carries the value its author believed was there; if that is no longer true, the write is refused and the author is told what the field now holds, so it can decide rather than guess.

This matters most where a machine and a person are both acting on one issue — the machine retries against the new value instead of undoing what the person just did.

Long comment threads are read in pieces

A thread longer than one response comes back a page at a time, with a marker for where to resume. A reader that ignores the marker sees the first page and believes it saw the thread. Anything counting or summarising a discussion must follow the marker to the end, or it is reporting on a prefix.

When it goes wrong

What you seewhat is happeningwhat to do
A comment shows raw markup instead of a formatted block. The stored text is structured, but whatever is displaying it could not interpret the structure, so it fell back to showing the characters. Read it through the tracker's own screen, which understands the structure. If that is where you already are, the body was stored in a form nothing can render — rewrite it.
A backlog report by module shows more issues than exist. Primary and secondary counts were added together. One issue attached to a module in both roles is counted twice. Read the two numbers separately. They answer different questions and were never meant to sum.
An automated worker's comment is refused. That stage demands a structured answer and the worker sent prose. Nothing — the refusal names the missing part. A person writing the same comment is never refused, so this is not a tracker fault.
An attachment is missing after an upload that seemed to work. A file is judged in one place regardless of which route carried it. A route that reported success before that judgement leaves nothing behind. Re-upload and watch for the refusal message, which names the size or type rule that stopped it.
