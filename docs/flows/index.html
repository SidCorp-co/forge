Flow diagrams

One file per flow. A flow is something that moves — a request across processes, a lifecycle, a decision path. Not a box diagram of what exists; docs/modules/ already owns structure.

Rules

  • Backfilled by the work, never as a project. An issue that touches a feature or module backfills that flow in the same change. Nobody is assigned to draw the missing ones.
  • One flow per file, named <domain>-<flow>.html, and listed in the table below in the same commit. A file not in the table is unreachable and counts as missing.
  • Show the mechanism. The test is whether a reader who has not seen the code can say what happens when it goes wrong. A diagram that only names the components has not earned its file.
  • Pick the form from the question — sequence when the point is who talks to whom and in what order; state machine when the point is which transitions are legal; flowchart when the point is where a decision forks. Inline SVG or a <pre class="mermaid"> block, self-contained, opens from disk with no build step.
  • Delete rather than carry. A flow the code no longer performs is removed in the change that discovers it — not marked stale.
