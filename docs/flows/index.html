Rules — how a flow in this folder is drawn
  





    
  
  • Backfilled by the work, never as a project. An issue that touches a feature or module
      backfills that flow in the same change. Nobody is assigned to draw the missing ones.
    • 
  
  • One flow per file, named <domain>-<flow>.html, and listed in the
      table below in the same commit. A file not in the table is unreachable and counts as missing.
    • 
  
  • A flow states the RULE, never the code that carries it. Who owes the next move, what
      each party may and may not do, what the system refuses and what the person is told. A function
      name, a file path, a SQL clause, a migration number or a test file is the implementation of the
      rule — it belongs at the foot of the page as a pointer, never inside the figure, the caption or
      a table cell. The rule outlives three rewrites of the code under it; a page written against
      symbol names is stale the first time somebody renames one, and stale in silence.
    • 
  
  • Show the mechanism, in the business's own words. The test is whether a reader who has
      never opened the repository can say what happens when it goes wrong, and what they should do
      about it. A diagram that only names the components has not earned its file.
    • 
  
  • Cite a measurement, not a changelog. A number that proves the rule earns its line (how
      many rows, how many minutes, how many projects). An account of which issue changed what, in
      which order, does not — that history already lives in the tracker and the changelog.
    • 
  
  • Pick the form from the question — sequence when the point is who talks to whom and in
      what order; state machine when the point is which transitions are legal; flowchart when the
      point is where a decision forks. Inline SVG or a <pre class="mermaid"> block,
      self-contained, opens from disk with no build step.
    • 
  
  • An edge that leaves from EVERY node is a band, not N arrows. Draw it once as a labelled
      strip with a tick down to each node it touches. issue-status-lifecycle spent 29 of
      its 59 edges on three universal exits and rendered as a hairball; the same three facts are one
      band and one footer.
    • 
  
  • The figure is the page; prose is a caption. The landing view is the diagram, a legend,
      and at most three lines under it. Everything else goes in a tab or a table row. If a
      paragraph is needed to explain the diagram, fix the diagram.
    • 
  
  • Lay it out like a screen, not a document. A header bar naming the flow and its one-line
      status, the figure on its own panel, a right rail for the per-node reference, tabs for the
      detail. The reader is scanning, not reading top to bottom.
    • 
  
  • Hand-author the SVG when the layout carries meaning. A layout engine given 14 nodes packs
      them and shrinks the type until nobody reads it. Mermaid is right for a short chain; past ~10
      nodes or ~20 edges, place them yourself. Keep the figure in a scrolling panel
      (overflow-x:auto) with its grid column at minmax(0,1fr), or a wide
      figure drags the whole page sideways.
    • 
  
  • A figure that renders is not a figure that is legible. Mermaid defaults to
      useMaxWidth, which fits a wide diagram to its column by scaling the whole SVG
      down — type included. Measured across this folder 2026-09-11: the worst was
      agent-execution at 0.21× (2412px of diagram squeezed into 514px, 16px type
      rendering at about 3px), and organization-access at 0.38×. Every file here now
      initializes with startOnLoad:false, a 12px base font,
      flowchart.useMaxWidth:false, and a fit() pass that sets each SVG's
      width from its own viewBox — CSS cannot read a viewBox, so this cannot be done in
      the stylesheet, and a width rule carrying !important there silently
      beats the script. Attach it with .finally: mermaid.run() REJECTS on
      some diagram types after drawing them correctly, and a .then leaves exactly those
      figures shrunken.
    • 
  
  • Check that the figure draws at all. agent-execution-session-turns shipped
      marked drawn with two <pre class="mermaid"> blocks
      and no mermaid script on the page — for as long as it existed it showed
      stateDiagram-v2 [*] --> Spawning as literal text to every reader.
    • 
  
  • Delete rather than carry. A flow the code no longer performs is removed in the change
      that discovers it — not marked stale.
