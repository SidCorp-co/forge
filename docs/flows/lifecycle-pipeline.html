How an issue becomes work, and how that work ends

work and the record of it end together, or the board lies

A stop earns its place when a different party owes the next move at it — not when there is more work left to do. Parking (a question owed, or a deliberate pause) can happen at any live stop and is a different thing from waiting in the queue: a park names a person, and no queue will ever move it. The ladder is advice. Only two moves are actually refused — work that has not started cannot jump into the middle, and nothing may be put back to not-started.

2Work and the record of it end together — in both directions

  R --> Q2{"the last piece finishes"}
  Q2 --> F2["the batch must close, on that last piece's outcome.
A batch whose last piece FAILED

  F1 --> G["the board shows what is really happening"]
  F2 --> G

Defending only the first direction is what produced the symptom worth remembering: 98 of 114 batches sat marked as running with every piece under them already finished, across 18 projects — presenting as work in flight that no machine was doing. Anything that marks a batch finished must go through the one path that also settles its pieces; there is exactly one writer on each direction, by design.

Seeing a piece of work is not permission to start it. The two lists exist so a box can show what is coming without that acting as a decision to begin — and a project that declares a backlog stop it never admits leaves work visible forever and started never.

Where the answer is a person, no queue will move it. Those are the only stops where age means something is wrong.

A stop says where work is queued. It never says code exists.

in progress means a machine is holding it, not that a line was written. developed means somebody says code exists and the proof is still owed. The claim that work reached the product is made in exactly one place — the shipped mark, written when an issue closes. Anything reporting on delivery reads that mark, never the stop.

Both endings release whatever was queued behind them. Only closed claims something was delivered; dropped releases the queue too, but tells each waiting item that what it needed is never coming.

Before an issue may close, the record must say what shipped

Closing is not just a status. The external record of what went out has to carry an entry, and three narrow cases are exempt — work that changed nothing a user can see, work already recorded under another entry, and work that never shipped at all. Everything else is refused until the record exists.

The rule is enforced at both doors — the one a person uses and the one a machine uses — because a rule enforced at one door is a rule at neither.

When it goes wrong

What you seewhat is happeningwhat to do
The board says work is running, but no machine is doing anything. A batch was left marked running after everything under it finished. It holds nothing up, but every reader believes work is in flight. Close the batch on the outcome of its last piece. If it happens repeatedly, something is marking batches finished without going through the one path that settles their pieces.
An issue sits open with the shipped mark already set, and nothing is running. The run that owed the close died. Two separate passes notice this — one within a minute, one on a six-hour grace — and neither closes the issue, deliberately: the shipped mark is asserted by whoever landed the work, so the honest act is to show a person who can check. Check whether the work really shipped, then close it yourself. Two issues were found serving production while the tracker said the work had not started.
Work is visible in a project's backlog but never starts. The project declared a stop as backlog-visible but nothing ever admits it to the claimable queue. Admit it explicitly, or stop declaring that stop. Visible-but-unstartable is the one state that looks healthy and never moves.
A box's work session is half-closed — the record ended, the workspace did not. Closing takes three separate marks and one was never set. If the box that owned it is gone, a ten-minute grace lets somebody else finish the close. Wait out the grace before intervening. Clearing it by hand earlier races the box that may still be alive.
