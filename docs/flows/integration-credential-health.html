integration-credential-health — a refused API call becomes an operator instruction

An adapter calls a provider and is refused. This is the fork from that HTTP status to the words an operator reads, and what each branch tells them to do. Owners: packages/core/src/integrations/<provider>/adapter.ts (the fork), packages/core/src/integrations/status-service.ts (the bucket), packages/web-v2/src/features/integrations/derive.ts (the pill).

401 and 403 are different instructions, and this fork is the only place they can still be told apart. Downstream everything sees is a lastHealthStatus string on the connection row; nothing there can recover which status produced it. A 403 folded into needs_reauth tells the operator to replace a credential that works, and re-entering the same credential reproduces the state exactly (ISS-924).

What each hop does when it fails

HopWhereWhen it goes wrong
the call is refused coolify/client.ts CoolifyClient.request The route is lost if the error does not carry it. CoolifyApiError.route is populated at the one throw site precisely so the message downstream can name what wanted the ability.
rotation fallback coolify/client.ts, gated by isPreviousCredentialValid Only a 401 retries with previousApiToken. Letting a 403 through costs a round trip against a token with the same scope and puts a second identical failure in the log.
classify coolify/adapter.ts classifyCoolifyFailure The failure mode this flow exists for: 401 and 403 collapsed into one verdict. Both adapter call sites — health and deploy — go through the one classifier so they cannot drift apart.
persist integrations/store.ts → integration_connections.last_health_status A free-text column. An unrecognised value falls to the error bucket downstream, which is safe but silent — a new HealthStatus member must be added to status-service.ts and derive.ts in the same change.
bucket status-service.ts healthToStatus Both credential states are operator-actionable, so both bucket to attention, never error. The raw status is what the UI reads to tell them apart.
render web-v2 derive.ts DIRECTORY_STATUS_META Two states sharing one label is the same defect one layer up. Each carries its own label and the action it implies.
