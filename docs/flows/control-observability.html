control-observability — a fault on a box reaches an operator

A job wedges on a runner. This is every hop from that row going stale to a person seeing it and reaping it, and what each hop does when it fails. Owners: packages/core/src/admin/alert-queries.ts (the one detector), packages/web-v2/src/features/operator/ (the screen).

One detector, two deliveries. computeAlerts() is called by the pull route and by the sweeper. Neither inlines its own query, so the bell and the screen cannot disagree about whether something is wrong. A sixth alert added to one of them and not the other is not a thing that can happen.

The hops

What each hop does when it fails

HopFails howWhat the operator sees
computeAlerts() a query throws The GET 500s and the feed shows its own ErrorState with a retry. The sweeper swallows the throw into zeros instead, so the push half goes quiet while the pull half says so — the screen is the honest one.
GET /admin/alerts caller is not on ADMIN_EMAILS 403 ADMIN_ONLY. The /admin route is already 307'd away by src/middleware.ts before this, so in practice only a direct API call sees it.
the feed one of the four panels rejects That panel alone renders its error and retry. The other three keep their data — a whole-screen error would cost three working panels to report one broken endpoint.
POST /jobs/:id/cancel job already terminal 409 NOT_CANCELLABLE → error toast. The alert clears on the next refetch anyway, because the job that raised it is no longer stuck.
the WS room socket down, or subscribe.denied Nothing arrives and nothing says so. The reap's own invalidateQueries(['admin','ops']) is why the screen still updates for the action the operator just took — the live path is the bonus, never the mechanism.

The two things nothing type-checks

The room list. pipeline_run.status_changed publishes to project:<projectId> and to no cross-tenant room. The console therefore joins one room per project it lists, and ws/server.ts canSubscribe admits a project: room on project role or the ADMIN_EMAILS allow-list. Drop that second arm and every room past the operator's own memberships answers subscribe.denied: the numbers stay cross-tenant, the refresh quietly does not.

The query key. routeEvent invalidates by prefix. Every operator query is keyed ['admin','ops', …] and nothing enforces that but features/operator/hooks.live.test.tsx, which drives the real hooks and the real router rather than restating either key.
