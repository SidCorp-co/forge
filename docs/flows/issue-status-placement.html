What a status claims, and who is owed the next move

placement, never evidence

1The five exits from draft — one mints work, four do not

A session already in the worktree takes in_progress; one that pushed its branch and cannot merge takes developed. Promoting to open instead races a dispatched agent against the session already building the branch (ISS-933).

2When the run that owed the close dies

Both passes read the same three facts. Neither closes the issue — merged_at is caller-asserted, so the honest act is to show a person who can check. Observed on ISS-920 and ISS-931, both serving production while the tracker said work had not started.

A status answers placement and nothing else. The two were welded together until 2026-09-06: four runs reached one identical state — built, pushed, PR open, nothing merged — and recorded four different statuses, each honouring a different documented promise (ISS-940).
