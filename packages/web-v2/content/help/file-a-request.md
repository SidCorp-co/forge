# Ask for a change

Anything you want built, fixed or changed is filed in Forge as an **issue**. An
agent works from what you write, so the issue is the whole brief: what it says is
what gets built. This page covers what to write so the work can start without
anyone coming back to ask.

## Before you start

- You need access to the project. If you cannot see it, see
  [Troubleshooting](?path=troubleshooting).
- Know what you want to *happen*. "The export button downloads a spreadsheet" is
  something someone can build and you can check. "Export is weird" is not yet.

## Steps

1. Open the project and choose **New issue** at the top of the page.
2. Stay on the **Standard** tab. **Quick capture** is a shorter form — a one-line
   title and some optional context, with no attachments.
3. **Title** — the result you want, in one sentence.
   - Easy to act on: *"The invoice PDF shows the customer's billing address"*
   - Hard to act on: *"Invoice bug"*
4. **Description** — write down:
   - what happens today,
   - what you expected to happen instead,
   - where you see it: the page, the button, the account,
   - for a problem, the steps that show it, one per line,
   - why it matters: what it blocks, and for whom.
5. **Attachments** — a screenshot or a short screen recording saves a paragraph.
   Drop files on the box, choose them, or paste a screenshot straight in. Up to 10
   files, 10 MB each.
6. **Priority** — how much this matters next to your other issues. It starts at
   **Medium**. **Complexity** and **Category** are optional; leave them empty if
   you are not sure.
7. Choose **Create issue**. You land on the new issue's page.

## One change per issue

Two things to ask for are two issues. Each one is then finished, checked and — if
it comes back wrong — reopened on its own, without holding up the other.

## What is not an issue

An issue asks for a change you will be able to check. These do not:

- a question about how something works,
- a note or an idea you want to keep,
- something that has already been done.

An agent that picks one of these up may set it to **Dropped** and leave a comment
saying why. Dropped is final — see [Read an issue's status](?path=issue-statuses).

## What happens next

Look at the status on the issue's page. It shows one of two things, depending on
how your project is set up:

- **Open** — the work is with the pipeline. Nothing is needed from you.
- **Draft**, with an **intake** label — your project reviews new issues before any
  work starts. Nothing runs until someone with access to the project moves it to
  **Open**.

From then on the status says who holds the work. If an agent needs something from
you, the status becomes **Needs info** and its question appears on the issue page.
Answer it there.

## Verify it worked

- The issue is on the project's Issues list, under **All**.
- Its page shows your title, description and attachments.
- If a file did not attach, a message names it and says why. Open the issue and
  attach it again.

## Troubleshooting

| Symptom | What is going on |
|---|---|
| Choosing **New issue** only says to open a project | You are not inside a project. Open one, then choose **New issue**. |
| The issue stays at **Draft** | Your project reviews new issues first. Ask whoever runs the project to move it to **Open**. |
| An agent asked you something | Answer it on the issue page. The work continues once you do. |
