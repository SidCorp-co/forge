**Forge tells the agent what is owed instead of writing it from a hook or a guess.** A merged change request with no merged mark asks its agent to mark it; an issue marked after a release that may already hold it asks its agent to record which release shipped it (`POST /api/projects/:id/shipped-in-records`); a promotion release carries the roster and the change request its agent names. Under a yolo gate profile, a merge naming no issue is owed to the master as a filing rather than filed by Forge (REQ-76 BC-8 r2), and a change-request release closes on Forge's own merge or the agent's mark, never on the host's report. No release, readiness or attention read calls GitLab any more, and a webhook writes no issue, release or roster state.
