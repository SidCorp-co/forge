**An issue on a project with no production environment can close.** Its landing on the working branch is its delivery: `POST /api/projects/:id/release-records` now records that landing — the branch, the commit, and that nothing was deployed — and closes what it claimed, refusing by name an issue whose merge is not in that commit or a criterion without a pass judged there or at a commit holding it. The steward's output check and a requirement's coverage count a verdict on that same landed build, so a pass at the landed head no longer reopens the issue or reads not judged, and a pass at the head before the merge still does not count. The Releases list and an issue's release line say "Landed on <branch> at <sha> — no environment".
